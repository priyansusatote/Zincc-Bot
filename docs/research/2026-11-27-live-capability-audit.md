# What a signed-in user can do in Zincc

27 November 2026, Windows, local workbench. This review covers the running product and the execution paths behind it. Only synthetic data was used for the new model-read test. A ready account in the UI records the connector's sync state. It does not by itself qualify every provider operation.

## Where the model can take action

**Packaged workbench verification.** The signed-in browser displayed all four planner choices and five named API routes plus two presets. Gmail and Calendar authorization were selectable, and sample setup was opt-in. One live TokenRouter DeepSeek request selected the recent-item operation. The workbench returned and rendered three sample summaries. Access was tested through the session security filter after correcting the route matchers. No live subscription run or personal mailbox read was part of this verification.

- **Chat app read.** One planner request selects a permitted action. Spring rechecks the selected account, reads up to three locally synced items and returns them to the browser. It currently supports listing recent items. It cannot send mail, search bodies, aggregate across accounts or look up live weather. [Dispatcher](../../src/main/java/io/zincc/integrations/ChatSourceApi.java)
- **Task agent.** The harness supplies allowed actions and the last observation. It validates a proposed list, create or finish step. Listing reads the actual configured task connector. Creating binds approval to one proposed task and records the provider outcome. Temporal handles waiting, bounded steps and recovery. [Agent engine](../../src/main/java/io/zincc/agents/AgentEngine.java) · [Workflow](../../src/main/java/io/zincc/agents/AgentWorkflow.java)
- **SDK planners.** Google ADK runs an agent, LangGraph compiles a one-node graph, and PydanticAI uses a function model. Each exchanges a single inference request with Spring and proposes a validated next step. The platform does not expose the full LangChain tool collection to chat. [Worker code](../../worker/frameworks/adapter.py)
- **MCP.** The briefing client lists tools on its curated server, checks the expected schema and calls the briefing tool. This is an actual MCP exchange in the routine flow. A routine can execute this fixed tool without an LLM. Installing arbitrary MCP servers from the workbench is still pending. [Briefing client](../../src/main/java/io/zincc/integrations/BriefingTool.java)

## What should change next

1. **Finish one daily job in a single thread.** A user asks for a briefing since a specified time. They choose accounts once. Zincc reads permitted sources, shows coverage and timestamps, links individual evidence where the provider supports it, and offers an editable follow-up. Acceptance includes an expired grant, a partially available account set and an empty morning.
2. **Make tools reusable across chat, agents and routines.** Publish a catalogue of operations with read/write scopes, setup, freshness, sample status and last success. Start with the three existing feeds and the exact task-create approval. Qualify one new app end to end before widening the catalogue. A read in chat and a scheduled read should enforce the same resource grant.
3. **Make subscription setup understandable from model selection.** Show eligible account, device status, exact model and last successful use at selection time. Qualify a current OpenCode Free completion and direct ChatGPT consent independently. Add an accurate unavailable state when the device is offline.
4. **Judge expansion by task completion.** Assess an inbox briefing, a PDF-to-dashboard workflow and an approved follow-up using source accuracy, correct account, duplicate writes, recovery, time to completion and cost. Add new research providers or tools where those journeys fail. [Product scope and connector targets](../product-scope-and-connectors.md)

The agent roster and visible action receipts in the supplied UI references inform the first two journeys. OpenMausBot informed provider and model discoverability. OpenBot and Perplexity informed the persistent assistant and recurring-work goals. These are product references. No upstream UI or agent code was copied for this change.
