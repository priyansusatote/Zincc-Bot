# Tool discovery and collaborative design production

Reviewed 24 November 2026. Both references contribute design ideas. No upstream code, skills, assets or dependencies were imported. These additions are proposed work.

## Cloudflare Code Mode

Cloudflare's February article describes an MCP server exposing two tools. One searches API metadata and the other executes a short program that can call several endpoints and filter the results. Its approximately 1,000 versus 1.17 million token comparison measures the initial tool descriptions for Cloudflare's API. Discovery results, generated code, retries and final output also consume tokens. Anthropic independently describes processing intermediate results outside the model context. [Cloudflare article](https://blog.cloudflare.com/code-mode-mcp/) · [Anthropic engineering](https://www.anthropic.com/engineering/code-execution-with-mcp)

At the reviewed revision, the search implementation creates a separate worker for a search, and the policy module documents how the session's authorized accounts constrain account selection. The article's two-tool interface is the published design example. Zincc should measure its own catalog, which currently includes a small curated MCP surface. [Search implementation](https://github.com/cloudflare/mcp/blob/ad6cb102dbb875ce24cbafe761abf904f25d0d08/src/forge-tools/search.ts) · [Account policy](https://github.com/cloudflare/mcp/blob/ad6cb102dbb875ce24cbafe761abf904f25d0d08/src/forge-tools/policy.ts)

**P7.4 experiment.** Use the same read-only inbox, calendar and report fixtures with direct typed tools, grant-filtered schema lookup followed by ordinary calls, and a bounded program over brokered operations. Include one simple lookup and one paginated aggregation. Increase the fixture catalog size without widening the actor's grants. Compare a small/local model and a stronger route on task correctness, discovery and total tokens, calls, retries, elapsed time and data returned to the model. Prefer the simplest route that meets the measured workload. A model unable to generate reliable code can use ordinary calls.

For the executable variant, start with synthetic data in a qualified environment. The program receives limited operation handles. Every call must pass the server's current tenant, account, grant and quota checks. Cap fan-out, bytes, runtime and output, record per-operation receipts, and keep credentials in the broker. Verify that a grant revoked between pages prevents the next read. Future writes retain per-action approvals and idempotency. Exposing generated programs to customer data depends on the applicable P6 isolation gate.

## LangChain Content Studio

LangChain describes an editable project per Slack thread, design context supplied by the team, rendered previews and staged review. In the public repository the brand schema validates design tokens, fonts and copy rules. The workflow module defines run records, step keys and report validation. Zincc can reuse its existing job and artifact architecture for the same needs. [LangChain design article](https://www.langchain.com/blog/design-agent) · [Brand schema](https://github.com/langchain-ai/design-agent/blob/86d8f667796890eb6d3612dbd1b9e941782fe03f/src/design_agent/brand/schema.py) · [Workflow source](https://github.com/langchain-ai/design-agent/blob/86d8f667796890eb6d3612dbd1b9e941782fe03f/src/design_agent/harness/workflow.py)

**P10 product addition.** A user can take one source brief and a versioned workspace brand kit, approve a sample, and request related slides, social graphics, UI illustrations or a short video as the corresponding renderers qualify. Save editable sources, references, font and asset rights, and the exact approved revision. For motion, review the storyboard and a timed rough cut before the full render. Feedback names a slide, frame or timestamp. Changing an approved element invalidates the affected downstream approval.

**First acceptance journey.** From the workbench, make one slide and one social graphic from a synthetic launch brief. Change the launch date once in the shared brief. Both exports must show the corrected date, use approved fonts and colors, and link to the new source revision. Keep the earlier approved outputs recoverable. Check overflow, missing assets and human approval in the rendered outputs. A later Slack entry point must verify the requesting member's access on every edit and an explicit destination grant before posting. P5's read-only Slack connector supplies no posting permission.
