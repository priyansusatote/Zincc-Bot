# Choosing a model under a privacy constraint

**Implemented** capability-based selection and a deployment-wide local-only inference policy. Spring filters the registry before it constructs clients. With `zincc.local-only=true`, cloud IDs are unreachable even through an explicit caller. With no qualified local runtime the registry is empty. For each configured preset the selector picks the first eligible ID that supports the operation. The client submits the resolved ID, so replay and retry keep their original route.

**Experimentally evaluated** two configured free cloud routes on 22 November 2026. Both saw the same arithmetic and word-selection prompts, once each, with the profile's 512-token ceiling. Lightning matched one of two expected strings, with one invalid generation and 6.6 seconds across both calls. Gemma returned two provider errors in 1.3 seconds. These are end-to-end success counts. Gemma returned no answers to grade for reasoning quality. Re-run `RouteProbeTest` with `ZINCC_COMPARE_ROUTES=lightning-free,gemma-free` and the `openrouter-free` profile to compare another observation. Two samples cannot establish a model ranking.

**Trade-off.** A local service may relay prompts. The operator must disable Ollama cloud access, restart it and qualify the network boundary before setting `zincc.models.ollama-offline=true`. Locality describes inference on the control-plane host. The current check cannot attest the host, OIDC service or PostgreSQL deployment. The tests exercise explicit cloud selection, missing capabilities, an unreachable local endpoint and missing operator qualification.
